What an array actually is

A fixed-size, indexed block of same-type storage. Once created with new int[6], the size never changes — arr.length is fixed for that object's lifetime.

Memory layout int[] arr = {1,2,3,55,5,6}

Indexing starts at 0, not 1. The last valid index is always arr.length - 1 — that's why every loop in ArrayClass runs for(int i=0; i<arr.length; i++) rather than i<=arr.length. Using <= is the single most common cause of ArrayIndexOutOfBoundsException for beginners.

Two arrays live inside ArrayClass

1. int[] arr — a 1D array, passed into the constructor. Every method in the first half of the class (displayArray, searchArray, sumArray, reverseArray, sorting, isPalindrome, rotateRight, printSubArray) operates on this one field.

2. int[][] arraytwod — a hardcoded 3×3 grid, initialized directly in the field declaration. displayDoubleArray, sumOfArray, sumOfDiagonal, and the second findDuplicates() all work on this grid instead.

Traverse, Search & Sum

Three of the simplest array methods — but they establish the pattern every other method reuses: walk the index from 0 to arr.length-1.

displayArray() prints every element

public void displayArray(){
    for(int i=0;i<arr.length;i++){
        System.out.print(arr[i]+" ");
        System.out.println();
    }
}

searchArray(int) linear search

public int searchArray(int integer){
    for(int i=0;i<arr.length;i++){
        if(arr[i]==integer){
            System.out.println("the expceted data is received...");
            return arr[i];
        }
    }
    System.out.println("Data is not available during the search operation");
    return -1;
}

sumArray() running accumulator

int sumArray() {
    int sum = 0;
    for(int i = 0; i < arr.length; i++) {
        sum = sum + arr[i];
    }
    return sum;
}

Reverse & Sort

Both methods mutate arr in place using swaps — no extra array is allocated.

reverseArray() two-pointer swap

public void reverseArray(){
    int start=0;
    int end=arr.length-1;
    while(start<end){
        int temp= arr[start];
        arr[start]=arr[end];
        arr[end]=temp;
        start ++;
        end --;
    }
    displayArray();
}

sorting() compare-and-swap

public void sorting(){
    for(int  i=0;i<arr.length;i++){
        for(int j=i+1;j<arr.length;j++){
            if(arr[i]<arr[j]){
                int temp=arr[i];
                arr[i]=arr[j];
                arr[j]=temp;
            }
        }
    }
    displayArray();
}
NOTERead the condition carefully: if(arr[i] < arr[j]) swaps the larger value forward. That sorts the array in descending order, not ascending — a common surprise for students who assume "sorting" always means smallest-first.

Palindrome, Subarray & Rotate

Three independent utility methods on arr. Try the default array (not a palindrome), or edit it to build one.

isPalindrome() mirror check

public boolean isPalindrome() {
    int start = 0;
    int end = arr.length - 1;
    while(start < end) {
        if(arr[start] != arr[end]) {
            return false;
        }
        start++;
        end--;
    }
    return true;
}

printSubArray(start, end) bounded range

 void printSubArray(int start, int end) {
    System.out.println("Sub Array:");
    for (int i = start; i <= end; i++) {
        System.out.print(arr[i] + " ");
    }
    System.out.println();
}
Enter a start/end and click "Print sub-array".
NOTEThe loop uses i <= end, so end must always stay within 0 … arr.length-1 or this throws ArrayIndexOutOfBoundsException. There's no bounds check in the method itself.

rotateRight(k) k single-step shifts

 void rotateRight(int k) {
    k = k % arr.length;
    for (int count = 0; count < k; count++) {
        int last = arr[arr.length - 1];
        for (int i = arr.length - 1; i > 0; i--) {
            arr[i] = arr[i - 1];
        }
        arr[0] = last;
    }
}
NOTEEach of the k passes re-shifts every element — that's O(k×n) time. The same result can be done in O(n) with the reversal trick (reverse whole array, then reverse each of the two segments) — worth raising as a "can we do better?" discussion.

The 2D Array — arraytwod

A fixed 3×3 grid declared directly on the class. Rows are arraytwod[i], columns are arraytwod[i][j].

The grid

int[][] arraytwod={
    {10, 20, 30},
    {40, 50, 60},
    {70, 80, 90}
};

displayDoubleArray() two loops, back to back

public void displayDoubleArray(){
    for(int i=0;i<arraytwod.length;i++){
       for(int j=0;j<arraytwod.length;j++){       // ← inner bound uses arraytwod.length
           System.out.print(arraytwod[i][j]+" ");
       }
    }
    // another method which is right
    for(int i=0;i<arraytwod.length;i++){
       for(int j=0;j<arraytwod[i].length;j++){     // ← inner bound uses arraytwod[i].length
           System.out.print(arraytwod[i][j]+" ");
       }
    }
}
BUGThe first loop bounds the inner j by arraytwod.length (the row count, 3) instead of arraytwod[i].length (that row's own width). It only produces correct output here because the grid happens to be square (3 rows × 3 columns). Change any row to a different length and this loop throws ArrayIndexOutOfBoundsException or silently skips columns. The second loop is the version to actually teach.

Neither loop calls println() — both print space-separated values with no line break, so on a real run their output runs together on a single line. See the Program Output tab for the literal console text.

sumOfArray() visit every cell

public int sumOfArray() {
    int sum = 0;
    for(int i = 0; i < arraytwod.length; i++) {
        for(int j = 0; j < arraytwod[i].length; j++) {
            sum = sum + arraytwod[i][j];
        }
    }
    return sum;
}

sumOfDiagonal() arraytwod[i][i]

public int sumOfDiagonal() {
    int sum = 0;
    for(int i = 0; i < arraytwod.length; i++) {
        sum = sum + arraytwod[i][i];
    }
    return sum;
}

Finding Duplicates

The source defines two different duplicate-finders — one for the 1D array, one for the 2D grid. Both are named findDuplicates(). That's the headline bug, covered fully in Code Review; here we visualize what each one is trying to do.

1D findDuplicates() nested loop, i vs j>i

public void findDuplicates() {
    for(int i = 0; i < arr.length; i++) {
        for(int j = i + 1; j < arr.length; j++) {
            if(arr[i] == arr[j]) {
                System.out.println("Duplicate: " + arr[i]);
            }
        }
    }
}

2D findDuplicates() every cell vs every later cell

public void findDuplicates() {
    for(int i = 0; i < arraytwod.length; i++) {
        for(int j = 0; j < arraytwod[i].length; j++) {
            for(int x = i; x < arraytwod.length; x++) {
                int startColumn = 0;
                if(x == i) { startColumn = j + 1; }
                for(int y = startColumn; y < arraytwod[x].length; y++) {
                    if(arraytwod[i][j] == arraytwod[x][y]) {
                        System.out.println("Duplicate: " + arraytwod[i][j]);
                    }
                }
            }
        }
    }
}

This is the 2D equivalent of "compare with everything that comes later": for cell (i,j), it scans the rest of row i after column j, then every cell in all rows below. The real arraytwod (10…90) has no duplicates, so this demo uses a modified grid to show a match.

Code Review — the original source

Kept verbatim, typos and all. Two callouts below mark real defects; the rest are style notes worth discussing in class.

BUG 1 There are two methods named findDuplicates() in the same class, both with an empty parameter list — identical signatures. Java resolves overloads by parameter list, not by what the method does internally, so this is a duplicate method definition and will not compile: error: method findDuplicates() is already defined in class ArrayClass. Fixing it means renaming one, e.g. findDuplicates1D() and findDuplicates2D().
BUG 2 In displayDoubleArray(), the first inner loop uses j < arraytwod.length instead of j < arraytwod[i].length. It happens to work only because this grid is square (3×3). It is not safe for a jagged or non-square 2D array.
STYLE sorting() produces descending order despite the generic name — worth a naming discussion. rotateRight(k) is O(k×n); an O(n) version exists. Neither printSubArray nor searchArray validate their inputs before indexing.
