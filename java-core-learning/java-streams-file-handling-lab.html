Concept

A stream is a one-way conveyor belt for data

Your program never touches the disk. It asks the JVM for a stream object, and that object carries data one item at a time, in one direction, between a source and a destination. Change the source (file, keyboard, network socket, byte array) and the loop that reads it stays identical — that uniformity is the entire point of java.io.

  • One direction. An InputStream can only read; an OutputStream can only write. Need both? Open two streams.
  • Sequential. Item 5 cannot be read before item 4. There is no jumping back (that's RandomAccessFile, a different tool).
  • Finite. Every stream eventually signals "no more data" — -1 for read(), null for readLine().
  • A held resource. An open stream holds an OS file handle. Not closing it leaks the handle and can leave your data stuck in a buffer, never written.

⚠ The rule to memorise

Byte streams count bytes. Character streams count characters. For plain English ASCII they happen to match, so beginners never notice — until one ₹ or é appears and the two numbers disagree. Tab ③ runs exactly that experiment.

Chaining — how BufferedReader actually works

Processing streams take another stream in their constructor and wrap it. Data flows through the whole chain; you only ever talk to the outermost object.

 chaining.java

Reading right to left: the file gives bytes → FileInputStream carries bytes → InputStreamReader decodes bytes into characters → BufferedReader collects characters into whole lines. Each layer adds one skill and delegates the rest downward.

Why buffer at all?

An unbuffered read() asks the operating system for one byte per call. A buffered stream asks once for 8192 bytes and serves your next 8191 calls from memory. Same output, dramatically fewer system calls — this is why BufferedReader is standard in every real program.

Byte streams

InputStream & OutputStream — 8 bits at a time, no interpretation

Byte streams are the raw layer. They carry the exact bytes on disk and never ask what those bytes mean, which is why they work for every file type ever invented. The two workhorses are FileInputStream (read) and FileOutputStream (write).

The read() loop, byte by byte

This is the single most important mechanic in the unit. in.read() hands back the next byte as an int (0–255), then −1 forever after when the file is exhausted. Step the cursor and watch the return value.

notes.txt on disk — one cell = one byte
⛔ Why byte b = in.read(); is wrong

read() returns int, not byte. A Java byte is signed (−128…127) and has no spare value left to mean "end of file", so the API widens to int and reserves −1 as the sentinel. Assigning it to a byte is a compile error (possible lossy conversion), and casting it makes byte 255 arrive as −1 — your loop then ends early on a perfectly valid byte.

The new String(buf) trap

The last chunk of a file almost never fills the buffer. If you print new String(buf) you print the whole array — including leftovers from the previous chunk.

buffer size 4, file "GSEC 2026" (9 bytes) chunk 1 → buf = [G,S,E,C] n=4 chunk 2 → buf = [ ,2,0,2] n=4 chunk 3 → buf = [6,2,0,2] n=1 ← 2,0,2 are stale! new String(buf) prints "6202" ✗ new String(buf,0,n) prints "6" ✓

Same for writing: always out.write(buf, 0, n). Writing buf whole appends 3 junk bytes and your copy no longer matches the original.

Character streams

Reader & Writer — text, with the encoding done for you

A character stream sits one level above bytes. It reads bytes from disk and decodes them into Java char values using a charset (UTF-8 by default since Java 18). Writing runs the same process in reverse. The payoff is that you deal in text — including readLine(), which no byte stream offers.

Two sentinels, never mixed up

⛔ while ((line = br.readLine()) != -1)

Compile error — readLine() returns a String. A String can never equal an int. The end marker for readLine() is null.

✓ The two correct loops

while ((c = fr.read()) != -1) — character at a time, int sentinel.
while ((line = br.readLine()) != null) — line at a time, null sentinel.

readLine() and the missing newline

readLine() strips the \n. So printing lines back with println reproduces the file, but summing line.length() gives a smaller number than file.length() — one character short per line. Lab Ex.10.3 prints both numbers side by side so the gap is visible.

File handling

File is a name, not a file

new File("gsec.txt") creates an object that holds a path. Nothing appears on disk. The file is created the moment a writer opens it — or when you call createNewFile(). Understanding that separation removes most beginner confusion: f.exists() can be false on a perfectly valid File object.

⛔ The classic lab disaster

A student writes records in a loop and opens new FileWriter(f) inside the loop. Every iteration truncates the file, so only the last record survives. Open the writer once, outside the loop — or pass true.

Exception handling is not optional here

Every file operation is declared to throw a checked exception. The compiler forces you to either catch it or add throws to your method — there is no third option.

ExceptionThrown whenFamily
FileNotFoundExceptionopening a file for reading that does not exist, or opening a directory / read-only file for writingsubclass of IOException → checked

SecurityExceptiona security manager blocks the accessunchecked

Catch order: child before parent

FileNotFoundException extends IOException. Put the IOException catch first and the compiler rejects the file — the specific block would be unreachable. Same rule you learned in the Throwable unit, now with real classes.

Viva questions with the one-line answer

  • Why is read() int, not byte? To fit 0–255 plus the −1 end marker.
  • Difference between byte and character streams? 8 bits vs 16-bit chars; character streams apply an encoding, byte streams do not.
  • Why is Reader abstract? It defines the contract; the source-specific subclass supplies the actual reading.
  • What does flush() do? Forces buffered data out immediately, without closing.
  • Is FileNotFoundException checked? Yes — it extends IOException extends Exception.
  • Purpose of InputStreamReader? The bridge that converts a byte stream into a character stream.
  • Node vs processing stream? Node talks to the real source; processing wraps another stream to add a feature.
  • Does new File("x.txt") create a file? No — it only creates a path object in memory.
